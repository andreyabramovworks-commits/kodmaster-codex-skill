# Отладка и регрессионные тесты

## Root cause first

1. Expected/actual и минимальный сценарий.
2. Воспроизвести самым дешёвым надёжным способом.
3. Составить 2–4 ранжированные опровержимые гипотезы и альтернативную гипотезу.
4. Проверять по одному различающему факту; не менять код между измерениями.
5. Зафиксировать причинную цепочку.
6. Только затем минимально исправить первопричину.

Если воспроизведение невозможно, использовать characterization test вокруг наблюдаемого контракта или `NEEDS_VERIFICATION`. После трёх неудачных исправлений пересмотреть модель системы.

## Выбор теста

unit → integration → component → E2E → property/fuzz → characterization в зависимости от минимального уровня, который надёжно ловит регрессию.

Сначала red, затем green, если это практически возможно. Проверять публичное поведение, а не внутреннюю реализацию без причины.

Focused test → связанный suite → lint/typecheck/build по риску. Затем variant sweep по callers/sinks/validators/соседним состояниям.
