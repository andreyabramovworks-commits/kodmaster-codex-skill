# Маршрутизация и глубина

## Natural-language router

Определяй действие по смыслу, включая формы слов и английские эквиваленты. Не требуй `$kodmaster` или `/`.

| Намерение | Маршрут |
| --- | --- |
| «проверь всё приложение», «найди баги/ошибки/нерабочие функции», audit codebase | `/kodaudit` Discovery |
| «проверь, что Codex сделал», «можно сливать/выпускать?» | `/kodaudit` Acceptance |
| «проверь интерфейс/мобильную версию/доступность» | `/uiaudit` |
| «почини/исправь/реализуй» | `/apply`; при баге сначала короткий Discovery |
| «сделай план/сначала разберись/ничего не меняй» | `/kodplan` |
| «отправь в Codex/в отдельную ветку» | `/kodsend`, только при согласованном плане |
| «переведи/проверь грамматику/улучши текст/стиль» | writing profile |

Если пользователь явно говорит «только анализ», запрещены изменения. Если говорит «найди и исправь», анализ и исправление входят в одну задачу, но сохраняют отдельные фазы.

## Fast

Fast ограничивает работу:

- указанными файлами/сценарием;
- прямыми импортами, callers/callees и контрактами;
- быстрыми статическими проверками и минимальными тестами;
- одной-двумя наиболее вероятными гипотезами.

Fast запрещает утверждать, что весь репозиторий проверен. Эскалировать в Adaptive только при доказательстве системного риска и сообщить об этом одной строкой.

## Deep

Deep означает полный проход, а не «подумать подольше»:

1. Инвентаризация корня, языков, manifest/lockfiles, entrypoints, приложений, сервисов, БД, CI/CD и deploy.
2. Карта runtime-потоков и trust boundaries.
3. Все применимые технические треки.
4. Реальные пользовательские сценарии и состояния UI, если интерфейс доступен.
5. Тесты, сборка, линтеры и безопасные сканеры.
6. Variant sweep по найденным классам дефектов.
7. Явный список `NOT_ASSESSED` с причиной.

Не сканировать бинарники, vendor, generated, coverage и build output без специальной причины. Deep не разрешает активные атаки, destructive migrations или production writes.

## Adaptive (по умолчанию)

Начни с дешёвой карты и risk signals. Расширяй scope при наличии:

- auth/payments/permissions/PII/secrets;
- миграций, конкурентных записей, очередей;
- публичного API или внешней интеграции;
- повторяющегося бага/общего helper;
- отсутствующих тестов на критический путь;
- рассинхрона документации, CI и runtime.

Для запроса «всё приложение» Adaptive обязан дать репозиторный охват и становится почти Deep. Для локальной правки остаётся сфокусированным.

## Экономия токенов

- Сначала `rg --files`, manifests и конфиги; затем релевантные файлы.
- Хранить короткий candidate ledger: id, evidence, status, next check.
- Не повторять одинаковую первопричину для каждого симптома.
- Не вставлять длинные логи и исходники; давать путь/строку и краткий фрагмент только при необходимости.
- Запускать тяжёлые проверки после дешёвого отбора и по риску.
- Завершать ветку расследования, когда доказательств достаточно для решения.
