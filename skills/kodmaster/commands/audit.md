# /audit

## Назначение

Проверить проект или выбранную область без автоматического исправления.

## Области аудита

- архитектура;
- дублирование логики;
- CSS и UI;
- безопасность;
- API и обработка ошибок;
- миграции;
- тесты;
- Git workflow;
- мёртвый код и неиспользуемые стили;
- deployment artifact и rollback;
- observability и безопасное логирование;
- зависимости и уязвимости;
- API contracts и backward compatibility;
- стратегия тестирования и CI;
- надежность внешних API;
- производительность;
- UI states и accessibility;
- полнота Definition of Done.
- legacy CSS normalization и цепочки override/`!important`;
- единый modal/overlay viewport contract;
- конкурирующие render/load/bind реализации и ownership UI lifecycle;
- сохранение визуального контракта при архитектурном рефакторинге;

## Ответ

Группировать находки:

- критично;
- средний приоритет;
- низкий приоритет.

Для каждой находки указывать:

- наблюдение;
- место;
- риск;
- рекомендуемое действие.

Не исправлять до отдельного выбора пунктов и подтверждения плана.


## UI-аудит

Если основная цель запроса – оценить внешний вид, UX, адаптивность, состояния, accessibility или целостность интерфейса, использовать специализированную команду `/uiaudit` и правила `rules/ui-design-system.md`. Общий `/audit` может отметить UI-проблемы, но не заменяет детальный UI AUDIT.
