# Core Rules

Этот файл читается для каждой технической задачи KodMaster.

1. Не изменять файлы при read-only аудите или `/kodplan`.
2. Не расширять scope без причины; новый риск сначала зафиксировать.
3. Не уничтожать dirty worktree, чужие изменения, историю Git или данные.
4. Перед созданием новой реализации проверить существующие conventions и источники истины.
5. Любое утверждение о баге, тесте, CI, deploy или production должно опираться на фактическое доказательство.
6. Проверки выбирать по риску, но не пропускать обязательный rule pack ради экономии токенов.
7. Секреты и чувствительные данные не выводить и не коммитить.
8. Изменения данных, API, auth, migrations, production и shared UI считаются повышенным риском и требуют соответствующего rule pack.
9. При обнаружении нового слоя системы повторно выполнить Rule Router до изменения этого слоя.
10. Если правило проекта конфликтует с общим правилом KodMaster, подтверждённое проектное решение имеет приоритет только если оно зафиксировано и не создаёт очевидной угрозы данным/безопасности.
