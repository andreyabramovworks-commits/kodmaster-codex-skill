# Clean Code

- Файл должен иметь понятную основную ответственность.
- Точки входа содержат связывание и вызовы, а не всю бизнес-логику.
- Большую логику выносить в небольшие модули по ответственности.
- Не проводить несвязанный рефакторинг внутри исправления бага.
- Не создавать абстракцию раньше, чем подтверждена повторяемость.
- Сохранять существующий стиль проекта, если он не является причиной проблемы.
- Названия должны отражать поведение и предметную область.
