# CSS Architecture and Legacy Normalization

Этот файл является единственным каноническим источником CSS-архитектурных правил.

## Базовые запреты

- не создавать новый CSS-слой только для переопределения существующего;
- не исправлять визуальный дефект ростом specificity;
- не использовать `!important` как архитектурный пластырь;
- не создавать дублирующие/конфликтующие классы и media rules;
- не оставлять ставшие ненужными overrides и dead CSS в затронутой области.

## Перед изменением

1. Найти существующий источник стиля, token или component primitive.
2. Найти все правила cascade/specificity/media, формирующие итог.
3. Проверить точки использования.
4. Выбрать один канонический owner.
5. Изменить исходный owner, а не добавить нижний override.
6. Проверить связанные состояния и responsive behavior.

Новый стиль допустим для действительно нового визуального элемента, если нет подходящего существующего источника.

## Legacy Normalization

Если уже существуют цепочки overrides, много `!important`, fix/version-файлы, случайные px или конкурирующие media queries:

1. Зафиксировать текущий правильный итоговый визуал.
2. Найти цепочку правил, которая его собирает.
3. Выбрать канонический источник.
4. Собрать тот же результат в нём.
5. Удалить ставшие лишними overrides только в затронутой области.
6. Проверить визуальную и responsive-эквивалентность до/после.

Не проводить глобальную чистку незатронутого UI без отдельного согласования.
