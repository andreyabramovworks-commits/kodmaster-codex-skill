# API and Integrations Rules

- Валидировать входные данные и возвращать предсказуемые ошибки.
- Не ломать существующих потребителей API без согласованного перехода.
- Сохранять backward compatibility, если части системы могут деплоиться отдельно.
- Bitrix24 и аналогичные внешние сервисы вызывать через backend; секреты не передавать frontend.
- Использовать timeouts, обработку сетевых ошибок, bounded retries, rate-limit handling и idempotency там, где применимо.
- Повторные попытки не должны дублировать необратимые операции.
- Не менять внешний контракт без анализа consumers.
- Для webhooks проверять authenticity/signature, replay risk и idempotency, если технология это поддерживает.
- Ошибка внешнего сервиса не должна валить всё приложение без необходимости.
