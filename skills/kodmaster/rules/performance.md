# Performance Rules

- Не объявлять performance-проблему без measurement или достижимого антипаттерна.
- Не загружать большие объёмы данных без необходимости; использовать управляемую пагинацию.
- Не допускать N+1 и очевидных unbounded scans.
- Индексы добавлять под реальные WHERE/JOIN/ORDER BY, а не автоматически.
- Не выполнять тяжёлую логику в UI без необходимости.
- Lazy loading/dynamic import применять к реально тяжёлым или редким веткам.
- Избегать очевидных request waterfalls и лишних повторных запросов.
- Не проводить преждевременную микрооптимизацию без измерения.
- При доступности фиксировать до/после: latency, bundle, query plan, memory/CPU или другой релевантный показатель.
