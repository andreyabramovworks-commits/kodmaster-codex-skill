# KodMaster v4.1 — простая инструкция

## Что это такое

KodMaster помогает управлять разработкой обычными словами. Он сам определяет, что ты хочешь: план, исправление, аудит, UI-проверку или передачу задачи Codex.

Главное изменение v4.1: перед работой KodMaster отдельно определяет **какие правила разработки относятся именно к этой задаче**. Это Rule Router. Он экономит чтение, но не имеет права пропустить важное правило ради экономии токенов.

## Самый простой сценарий

Напиши:

```text
$kodmaster
Нужно исправить форму пользователя. Сначала составь план и ничего не меняй.
```

Или без команд:

```text
Сначала разберись в проблеме и дай план.
```

KodMaster выберет Fast/Adaptive/Deep, определит риск, подключит нужные правила и составит план.

После согласования можно написать:

```text
План подтверждаю. Отправляй в Codex.
```

Это то же намерение, что `/kodsend`.

## Что такое Rule Router

Это диспетчер правил.

Например CSS-задача подключит правила UI/CSS, но не будет читать правила PostgreSQL. Если во время работы выяснится, что причина UI-багa находится в API или БД, KodMaster повторно запустит Rule Router и дочитает правила API/БД **до изменения этого слоя**.

При сомнении KodMaster должен прочитать лишний важный pack, а не рискнуть забыть правило.

## Fast / Adaptive / Deep

- **Fast** — маленькая локальная область и прямые зависимости. Все обязательные правила всё равно читаются.
- **Adaptive** — режим по умолчанию. Начинает сфокусированно и расширяется по риску.
- **Deep** — полный проход по всем реально применимым частям проекта. Он не читает технологии, которых в проекте вообще нет.

## Команды можно не запоминать

`/kodplan` = «сделай план», «сначала разберись», «ничего пока не меняй».

`/apply` = «исправь», «почини», «реализуй план».

`/kodaudit` = «проверь приложение», «найди баги», «проверь что сделал Codex».

`/uiaudit` = «проверь интерфейс», «проверь мобильную версию», «сделай UI-аудит».

`/kodsend` = «отправляй в Codex», «поставь задачу Codex».

`/fast` = «быстро проверь только это».

`/deep` = «проверь максимально тщательно», «проверь всё приложение».

Полную краткую памятку всегда показывает `/kodhelp`.

## Как работает связка ChatGPT → Codex

1. Ты обсуждаешь задачу с обычным ChatGPT + KodMaster.
2. KodMaster формирует план и компактный task package.
3. `/kodsend` проверяет Git/GitHub, создаёт отдельную ветку и передаёт задачу Codex, если среда это реально поддерживает.
4. Codex работает с кодом.
5. KodMaster проверяет реальный diff и тесты.
6. `REWORK` — готовится узкая доработка без пересказа всей задачи.
7. `GO` — в разрешённом lifecycle ветка сливается в `main`, затем запускается реальный production pipeline.

Pull Request в стандартном single-developer workflow не нужен.

## Новые специальные профили v4.1

Они подключаются только если соответствующая технология реально есть в проекте:

- background jobs / queues — Celery, workers, cron, фоновые задачи;
- caching — Redis и другие кэши;
- file uploads/storage — загрузка и хранение файлов;
- realtime — WebSocket, SSE, Socket.IO;
- browser state/session — localStorage, sessionStorage, IndexedDB, session/token lifecycle и несколько вкладок.

## Важно

KodMaster не должен притворяться, что запустил Codex, GitHub action или production deploy. Без фактического tool/repository/pipeline evidence он обязан честно сообщить ограничение.
