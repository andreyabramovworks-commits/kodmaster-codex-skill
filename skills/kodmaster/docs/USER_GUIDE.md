# KodMaster v4 — простая инструкция

KodMaster можно использовать обычными фразами. Команды через `/` запоминать не обязательно.

## Примеры

```text
Используй KodMaster. Проверь всё приложение, найди реальные баги и нерабочие сценарии. Deep. Пока ничего не исправляй.
```

```text
Проверь интерфейс регистрации на компьютере и телефоне: UX, доступность, ошибки, загрузку, пустые состояния и тексты.
```

```text
Найди первопричину ошибки оплаты, исправь её и добавь тест, который не даст багу вернуться.
```

```text
Проверь русский и английский текст интерфейса: грамматику, перевод, единообразие терминов и переполнение элементов.
```

## Глубина

- `fast` — быстро и экономно: только нужная область и прямые зависимости.
- `deep` — максимально полный проход по всему применимому приложению.
- без слова — Adaptive: KodMaster выбирает глубину по риску. Просьба «проверить всё приложение» всё равно означает подробный репозиторный аудит.

## Основные команды

- `/kodplan` — план без изменений.
- `/apply` — выполнить согласованную работу.
- `/kodaudit` — найти проблемы во всём приложении или проверить уже готовый diff.
- `/uiaudit` — отдельно проверить интерфейс, UX, accessibility и тексты.
- `/kodsend` — передать согласованную задачу Codex в отдельной Git-ветке.
- `/kodhelp` — короткая справка.

Старая `/audit` работает, но является скрытым алиасом поиска проблем внутри `/kodaudit`.

## Что означают результаты

При поиске проблем: `SHIP`, `FIX` или `BLOCK`. При проверке готовой правки: `GO`, `REWORK`, `BLOCKED` или `EVIDENCE_REQUIRED`.

Отчёт содержит доказательство, влияние, первопричину, точное исправление, проверку и уверенность. То, что нельзя проверить, отмечается как `NOT_ASSESSED`.

## Важная безопасность

Обычный аудит не атакует живой сервер и ничего не удаляет. Активный pentest, destructive migration, push и deploy требуют отдельного разрешения или заранее согласованного lifecycle.
